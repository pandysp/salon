# Build decisions

Prefixes: **D** chunk 2 core, **A** chunk 4 authoring loop, **T** chunk 3 tools, **L** lead, **R** fixes from the core security review, **P** fixes from the pre-Funnel review, **R11** the owner's link-write decision (own section at the end).

## Chunk 2: core
| # | Decision | Why | Alternatives considered |
|---|---|---|---|
| D1 | **Rollback creates a new version** (vN+1 with vK's files + manifest, `restored_from: K`); the app room is cut back to vK's `room_seq`, later messages move to `archive` | Versions stay append-only and immutable; the rollback itself is an auditable event; a later publish just continues numbering | A "current version" pointer back to vK (history looks rewritten, the next publish number is ambiguous) |
| D2 | **Anonymous link viewers cannot read or write comments**; comments = owner + guests with a grant | The spec gives link mode "view and use the room"; comments feed pi, so an anonymous write path would be a spam/injection path into the authoring loop | Let link viewers comment (needs a moderation story first) |
| D3 | **Content CSP stricter than the spec**: spec directives plus `form-action 'none'; base-uri 'none'; object-src 'none'; frame-src 'none'; worker-src 'none'; manifest-src 'none'` | Each closes a fetch/navigation path the spec's list leaves to `default-src 'self'` (nested frames, workers, `<base>` tricks, form posts); no legit artifact needs them in v1 | Spec CSP verbatim |
| D4 | **`acceptInvite` kept** (a signed-in guest accepts a further invite without a new passkey); simplifier suggested dropping it | Without it the same person invited to a second artifact gets a second passkey and a second guest identity; use cases A and B will share guests; ~6 lines + one test step | Every invite registers a new passkey |
| D5 | **Ops scripts in `scripts/`** (`up.sh`, `down.sh`, `status.sh`), Dockerfile + entrypoint in `infra/` | The spec (the contract) names `scripts/up.sh`; the briefing said `infra/` | All in `infra/` |
| D6 | **The tailnet header counts only at `POST /api/signin/owner`** (allowlisted `Tailscale-User-Login`, no `Tailscale-Funnel-Request` marker, `Origin` = app), which mints an owner session (`__Host-session`, subject `owner`); everything else authorises by cookie or bearer token. Owner and agent *actions* are refused on Funnel traffic | Revised spec (Fable review): Tailscale attaches the header to every request from the owner's devices, so honouring it ambiently would let any page he opens act as him. Header stripping verified in tailscale v1.104.7 `ipn/ipnlocal/serve.go` (`addTailscaleIdentityHeaders`); the marker check is defence in depth. *Built first as header-on-every-request, reworked after the spec change* | Header on every request (first build) |
| D7 | **Every browser write (non-GET, WebSocket) must carry `Origin == APP_ORIGIN`** (no Origin = a non-browser client, which holds no ambient credential) and no cross-site `Sec-Fetch-Site`; GET has no side effects | In production the two hosts are the same site (`ts.net` is the PSL entry, so `<tailnet>.ts.net` is the registrable domain): SameSite never helps, and the content host is a "same-site" attacker | SameSite cookies only |
| D8 | **Content capability in the path** (`/c/<artifact~version~exp.sig>/…`, HMAC-SHA256, 12 h), **valid only while that version is current**; key generated once and stored in the Platform DB. Kept instead of the spec's random per-version token column | Same guarantees as the spec's token (unguessable, ≥128 bit, handed out only after the access check, dies with the version) plus an expiry; no table; a path prefix keeps relative URLs in bundles working. | Random token per version in a column (no expiry); query token (breaks relative URLs) |
| D9 | **Shell ↔ artifact over a MessageChannel** set up after the SDK's `hello`; the shell only forwards `room.send` (app room) and `tools.call` | One port per iframe load: no origin confusion on later messages, and the shell has a closed list of what an artifact may ask | Plain `postMessage` with origin checks per message (W3c) |
| D10 | **`$`-prefixed message types are reserved for the platform** in rooms; `$platform` version events are broadcast but not stored (since T16 the platform sends none: a new version closes the sockets. **Kept** so the platform can add a frame of its own again without colliding with stored artifact messages; one line of code. Deleting it is the lead's call) | Lets the shell tell platform events from artifact messages without changing the bake-off protocol; a client's `$` frame is refused (socket closed 4003), never stored and never reaches other sockets. (The shell does not trust the frame's content anyway: it re-reads the version from `/api/view`.) | A separate control socket |
| D11 | **Worker pre-bundled by esbuild** into `app/worker.js` (shell JS/CSS and SDK inlined as strings) | The image needs no `node_modules`; one file to deploy; celld still re-bundles it unchanged | Let celld bundle `src/` (needs node_modules in the image) |
| D12 | Bundles are **text files only** (html/js/css/json/svg/txt) | Less validation surface in v1; images can be `data:` URIs or inline SVG | base64 binary files |
| D13 | **Rollback to vK = the live room is exactly the messages with seq ≤ vK's `room_seq`**, wherever they are: later live messages move to `archive`, archived ones with seq ≤ that come back | Makes rollback reversible (rolling forward to v2 after rolling back to v1 brings v2's state back) and keeps "archive = what is currently rolled away"; nothing is deleted; seqs are never reused (SQLite AUTOINCREMENT) | Archive-only (a later roll-forward could never restore the archived state) |
| D15 | **pi = one `AGENT_TOKEN` from config** (bearer, identity `agent`): may list, read details and publish; no sharing, invites, rollback, events; refused on Funnel traffic; **no comments-room access yet** | Revised spec: pi never acts as owner. One token in `infra/<mode>.env` is enough for one pi; the comments gate (only the owner's and forwarded comments reach pi, by push and by `get_comments`) is chunk 4's, so until then pi cannot read comments at all | Token table with minting UI (more machinery than one agent needs) |
| D16 | **Local test stack on HTTPS**: the test proxy terminates TLS with a self-signed cert made per checkout (`tests/support/tls.mjs`); Chromium trusts it via `--ignore-certificate-errors-spki-list` (WebAuthn refuses cert errors), WebKit via `ignoreHTTPSErrors` | Playwright's WebKit keeps no `Secure` cookie on `http://localhost` (sign-in returned 200, cookie jar empty), so no WebKit viewer could hold a session; production is HTTPS anyway | Keep http and drop the WebKit viewer locally |
| D17 | **Local hosts are same-site, like production**: `app.localtest.me` / `content.localtest.me` (not on the Public Suffix List, public DNS answers loopback for every name); global setup refuses to run unless both resolve to `127.0.0.1`/`::1` only | The lead asked for local same-site fidelity (45-min spike): it worked, so the suite now exercises the same-site attacks (parent-domain cookies reaching the app host; the browser reports `Sec-Fetch-Site: same-site`). Cost: the tests depend on someone else's public DNS (guarded) and need DNS at all | `localhost` vs `127.0.0.1` (cross-site: hides same-site attacks); `*.artifacts.test` + Chromium resolver rules (no equivalent for WebKit) |
| D18 | **Owner tools take no arguments from the page**; pinned args live in the manifest (`args`), the route refuses any client args (`args_pinned`) | Revised spec: a guest must not send own arguments to the owner's account; the check sits in the tool route now, chunk 3 runs the pinned call | Allow args equal to the pinned ones (more to compare, no use) |
| D19 | **Room caps**: 64 KB per message (close 4003), 100 messages per 10 s per socket (close 4008); messages still queued on a socket the room closed are ignored | Revised spec asks for size and rate caps; per socket is the simplest unit (a viewer could open several sockets: noted) | Per viewer (needs shared counters) |

| D20 | **"Top-level sign-in route" read as `POST /api/signin/owner`, called by the `/signin` page's button**, with a strict `Origin == APP_ORIGIN` check (a missing Origin is refused too) | The point of the spec's wording is that the header counts in exactly one place that a foreign page cannot drive; a POST that requires the app's Origin gives that without a GET that changes state | A GET navigation that sets the cookie (a cross-site link could log the owner in at will; GET would change state) |
| L2 | **Keep the native celld dev stack (`scripts/dev.sh`)** for negative controls and the dev loop | Each control patches code and restarts; native celld restarts in about a second, the container needs a rebuild | Controls against the container stack only |
| L3 | **Local stack name, ports and evidence dir from env vars** (`CORE_STACK_NAME`, `CORE_PROXY_PORT`, `CORE_UPSTREAM_PORT`, `CORE_EVIDENCE_DIR`); test runs write to untracked `.run/evidence/`. **One renderer, `scripts/local-env.sh`** (sourced by `stack.sh` and `dev.sh`, run by `tests/support/env.mjs`): it moves every `*.localtest.me:<port>` in `infra/local.env` and `infra/local.mcp.json` by `CORE_PROXY_PORT - 8340`, sets the docker `--add-host`s for the test MCP servers and the token key path (`CORE_TOKEN_KEY_FILE` or `.run/<stack>-token-key`, created 0600 by `up.sh`/`dev.sh`). Chunk 3's T14 (`scripts/tools-env.sh`, `scripts/local-mcp.mjs`) folded in and deleted | Chunks 3 and 4 run their own stacks in parallel; tracked evidence churned on every run. One renderer: the tests and the scripts cannot disagree about ports (before, `env.mjs` shifted the origins itself and `local-mcp.mjs` the MCP ports); the key next to the stack's other run files, not in a user config folder | Per-worker script edits; per-worker config files |


## Chunk 4: authoring loop
| # | Decision | Why | Alternatives considered |
|---|---|---|---|
| A1 | **The comments room enforces who may send what** (`src/worker/comments.js` `checkComment`, run by `room.js` for every message in a `comments:` room, and by the MCP tools): `comment` owner or invited guest; `forward` owner only, once, on someone else's comment; `reply` and `resolve` pi only, on a thread pi can see. Unknown fields are dropped; ids must be new | The shell is only a UI: the room must refuse a guest's `forward` or a fake pi reply sent over a raw socket (tested, 4 raw-socket refusals + controls) | Trust the shell's UI (any guest socket could forward its own comment to pi); owner/guest replies and owner resolve (no UI needs them yet; less surface) |
| A2 | **One gate function, `agentItems(messages)`**: pi sees the owner's threads and the forwarded ones, with pi's/the owner's replies and the resolved state. It feeds pi's socket (history on connect and after every append), `get_comments`, the check that pi may reply/resolve, and the shell's "for pi" badge. A thread's `seq` is the seq at which it became visible to pi (the forward's for a guest comment) | Spec: only the owner's or forwarded comments reach pi, *by push and by get_comments alike*: one function makes the two paths impossible to drift apart; the badge shows exactly what pi gets. Seq-of-visibility makes "last delivered seq" also cover a guest comment forwarded long after it was written | Separate filters for push and pull; per-item push frames with their own filter |
| A3 | **Which artifacts a pi session follows lives in the session** (`appendEntry("artifact-follow")`, restored on resume); a session starts following when it publishes an artifact (or, since A14, calls `follow_artifact`). **The last delivered seq per (origin, artifact) lives in one file next to the extension** (`integrations/pi/artifact-bridge.state.json`), shared by all sessions of that install. Consequence: a brand-new session gets no comments until it publishes (or republishes, or follows, A14) the artifact; then it gets everything above the saved seq, including comments made while no session followed it (tested). The seq is keyed by the full origin: the same platform reached under a new origin re-delivers its still-open threads once (at least once), never misses one | The owner runs many pi sessions in parallel: if every session followed every artifact in the state file, each comment would start work in all of them. The spec's file next to the extension stays the replay memory, so restarts, resumes and a fresh session that adopts the artifact all catch up | Follow every artifact in the state file (every session gets every comment); a `follow_artifact` tool (one more tool, not needed for DoD 7); follow on `get_comments` (needs hooking pi's MCP tool results). Key by host without port or by artifact only (two platforms on one host, like two local stacks, would suppress each other's comments: missed work instead of a duplicate) |
| A4 | **pi's replies and resolves are written to `comments:<artifact>` by the platform Worker** (MCP tool → `Room.postComment("agent", …)`, same rules and gate as sockets). Read the spec's "written only by the shell, never by artifact code" as: *never by artifact code*; the trusted writers are the shell (for people) and the Worker (for pi) | The spec's intent is that the artifact (untrusted page code) has no path to the comments room; pi is a trusted author with its own identity. Routing pi's replies through a browser shell would need a browser for pi | A separate replies store outside the room (two sources of truth for one thread); pi writing through its socket (works too, same rules; MCP is the documented path) |
| A5 | **MCP endpoint = `POST /api/mcp`, hand-rolled stateless JSON-RPC** (the spike's ~30 lines), `need("agent")`: the agent bearer token only, tailnet only; GET → 405 (no SSE stream, no sessions). Every tool is a thin call into `Platform.publish/listFor/access` and the room's `postComment/agentView` | Proven in the spike; checked here with the official SDK client (tests) and pi 1.6's own MCP client (`pi mcp list`, smoke run). The MCP server SDK would add bundle weight and Node-only transports for no gain | `@modelcontextprotocol/sdk` server transport; allowing the owner's cookie too (no browser client needs MCP) |
| A6 | **pi uses its own MCP client** (pi 1.6 reads `.pi/mcp.json` / `~/.pi/agent/mcp.json`) for `list_artifacts`, `get_comments`, `reply_comment`, `resolve_comment`; the **extension adds only push/replay and a `publish_artifact {name, dir}` wrapper** that builds locally and calls the endpoint's `publish_artifact`. The endpoint's own `publish_artifact` (manifest + files) is hidden from the model with `toolExposure` | pi 1.6 has a native MCP client (the spike's pi had none, so it proxied all tools). A bundle is ~30 KB of JS: the model must never emit it as tool arguments | Extension wraps all 5 tools as in the spike (more code, a second path to the same endpoint) |
| A7 | **Push = the gated history frame on every append, no diff**; the bridge delivers open threads with `seq > last`, as one follow-up user message, then saves the seq (at least once) | Simplest thing that replays correctly after any disconnect: every frame is the full view, so a missed frame never loses anything. Rooms are small | Per-item frames (the bridge would need history + incremental logic); Artifact Server's claim/ack mailbox or a server-side delivery table (more machinery; the spec puts the memory in the file) |
| A8 | **Bridge config from the environment only:** `ARTIFACTS_ORIGIN`, `ARTIFACTS_AGENT_TOKEN` (the same variable `mcp.json` expands into its Authorization header: one secret, one place), optional `ARTIFACTS_BRIDGE_STATE`. No test knobs in the extension | One variable for both consumers; production code stays free of test switches | A token file (two places to configure); a JSON config file; a CA or extra-headers option in the extension |
| A10 | **Test proxy "tailnet door"** (`CORE_PROXY_PORT+2`): every client there counts as a tailnet device and `Host` is rewritten to the main port. Used by the bridge test and by pi in the smoke run | pi and the bridge cannot send the per-run marker header; the door keeps that test detail out of the extension (test-only code) | An extra-headers env var in the extension; a second proxy instance |
| A11 | **`bundleArtifact` resolves solid-js & co from the repo's `node_modules`** (`nodePaths`) | pi writes artifacts in its own working folder (outside the repo); without it the build fails there | Install Solid in every artifact folder |
| A14 | **`follow_artifact {name}`: a session takes a page over without republishing** (bridge tool; same `follow(name, persist)` as after a publish, so the `artifact-follow` entry, resume and replay above the shared seq work unchanged; an unknown name fails with the MCP 404 from `get_comments`). **It does not make other sessions stop following**: A3 has no owner, so every session that published or followed a page keeps receiving its comments until it ends (ARCHITECTURE residual 10). No `unfollow_artifact`. Test `A14 follow` (`tests/loop.spec.mjs`), control | The README limitation: a second session (or a restarted one without its entries) could take a page over only by republishing it, which makes a new version just to listen. A tool reuses all of A3's state; nothing new is stored | Takeover with ownership (the last session to publish or follow is the only one that gets comments): needs new state shared across sessions (an owner per artifact in the state file, checked on every frame), not built without a rule from the lead; `unfollow_artifact` (needs a second entry type subtracted on resume: new state, so not "trivial" in the brief's sense); follow on `get_comments` (hooking pi's MCP results, A3) |
| A13 | **Refusals inside Durable Objects carry `status`** (`comments.js` throws `Error` + `status: 400`, no import) and callers check `instanceof UserError \|\| e.status` | Measured on celld 0.6.3: an error thrown in a DO arrives over RPC as a plain `Error` that keeps `status` but not its class (`instanceof` false); `comments.js` stays import-free so the shell can bundle it | `instanceof` only (every refused comment would be a 500) |
| A15 | **"Send to agent" is a real box for the owner (pin composer and Comments panel, on by default); unticked, the comment is stored with `forPi: false`** (only when false, owner only, boolean; anything else refused). `agentItems` lets an owner thread through only without it; `forward` now also accepts such a held owner comment, which then reaches pi "by the owner" at the forward's seq like a forwarded guest comment. Test `pin agent toggle` (`tests/pins.spec.mjs`), control | The owner 16:08. One optional field keeps the room, the bridge and the gate's single definition as they are; stored only when false, so every existing comment and the stored shape stay unchanged; one shared send helper for both composers | A new message type (e.g. `note`) with its own rules and forward path; storing `forPi: true` on every comment (changes the stored shape for nothing); the box only on pins (the panel's composer is the same send, so it was trivial) |

## Chunk 3: tools

| # | Decision | Why | Alternatives considered |
|---|---|---|---|
| T1 | **The Platform object makes every MCP call** (official SDK `Client` + `StreamableHTTPClientTransport`, one session per call), **serialised per (subject, server)** by an in-memory promise chain | v1 runs no artifact server code, so the platform is the only MCP client. Servers may rotate refresh tokens (W2a's does, tested): two parallel refreshes would invalidate each other and log the viewer out. (Attio does not rotate: a refresh returned the same refresh token, access tokens live 24 h; checked 2026-11-23.) The single Platform object is the one place where "one at a time per connection" holds | The spikes' facet-era parts: per-request viewer capability, a `ViewerStore` object per viewer, a `Gateway` WorkerEntrypoint (all exist because artifact code ran on the server; v1 has none). Calls from the Worker (no serialisation guarantee) |
| T2 | **Egress allowlist = the owner's MCP config**: each server's own origin plus its declared `oauthOrigins`, exact origin match (scheme, host, port), enforced by `gatewayFetch`, the only `fetch` the SDK gets (transport and OAuth discovery, registration, token). Redirects: `redirect: "manual"`, never followed across origins | One list, no drift (spec). celld has no SSRF guard (W2b), so this check is the guard. Paths are chosen by platform code and the SDK, not by artifacts, so origin-level is enough; OAuth paths vary per server | W2b's `METHOD origin+path` list (every OAuth path listed by hand); a separate allowlist file (drift) |
| T3 | **Tokens encrypted at rest**: AES-256-GCM, one sealed blob per connection (OAuth client, tokens, PKCE verifier, pending state), additional data `subject\|server` so a blob cannot be moved to another row. Key from a **secret file** (`TOKEN_KEY_FILE`, created 0600 by `up.sh`), mounted read-only, written into `/app/.dev.vars` in the container layer (not the data volume) | The data volume alone reveals nothing (tested by grep, with a control and a negative control). The key never sits next to the ciphertext | Key in the Platform DB (next to the data); per-field encryption (more code, same protection) |
| T4 | **OAuth `state` lives in the connection row** (its SHA-256 in `state_hash`; the value inside the sealed blob, 10 min); the callback finds the row by it and **only the subject that started the flow can finish it** (cookie subject = row subject). `GET /api/connect/callback` is the one GET with an effect (the OAuth redirect needs it); start is a POST | One table for connections; a foreign page cannot complete a flow for someone else (tested: Bob gets 403 on Carol's state, negative control). Attio also refuses authorize requests without `state` | A separate pending-flow table |
| T5 | **Consent per (viewer, artifact, version)**, only "yes" is stored; "not now" lives in the shell's page memory (a reload asks again). The owner is asked too (viewer tools use *his* account when he views). The server refuses viewer tools without consent (`consent_required`) | Spec: "per artifact version"; every viewer-tool version needs the owner's approval anyway (T6), so asking again per version costs little and covers changed code using the same tools | A fingerprint of the viewer-tool set (no re-ask on unchanged tools); storing declines (needs a "change my answer" UI) |
